# 수학 서술형 문항 생성 도구 — 설계 초안 (v0)

작성 기준: 국어 도구 `docs/설계_결정사항.md`(항목 1~10)를 수학으로 옮길 때의 변경점·결정 필요 사항.
근거 자료: `docu/` 6개 PDF(경기 2025 논술형 길라잡이, 중등 교과별 논술형 문항 수학, 서울 초3·초6 서·논술형 자료 등).
상태: **초안.** `02-3`(이미지 PDF, OCR 필요)과 `02-2`(중등 수학 156쪽)는 아직 일부만 확인함.

범례: ✅ 국어 설계 그대로 재사용 / 🔧 수학용 수정 / ❓ 사용자 결정 필요

---

## 0. 수학이라서 달라지는 핵심 5가지

1. **수식·도형·표·그래프가 문항의 일부다.** PDF에서 텍스트를 뽑으면 수식이 깨진다(분수·지수·기호). 제시문(글) 중심이던 국어와 달리 "제시문" 자리에 **상황 + 수식 + 그림**이 들어간다.
2. **정답이 검증 가능하다.** 국어는 AI 점검이 전부였지만, 수학은 계산 결과·예시답안을 **코드(SymPy 등)로 검산**할 수 있다. 신뢰도의 가장 큰 이점이자 필수 장치.
3. **채점이 과정 중심·다양한 풀이 인정.** 채점기준은 "개념 이해 → 식 세우기 → 계산 → 결론 표현" 같은 단계별 분할 점수. "수와 식으로 표현한 풀이 과정이 논리적이면 정답 인정", "단위는 평가하지 않음" 같은 **채점 유의점**이 사실상 필수.
4. **서술형/논술형 구분이 학교급마다 다르다.** 초등(3·6학년)은 "개념을 글로 설명·실생활 예시"가 중심, 중·고는 "탐구·일반화·문제해결 과정 서술"이 중심.
5. **국어의 '적합/조건부/부적합(essayFeasibility)'은 수학에서 의미가 달라진다.** 저작권 때문이 아니라, "계산만으로 끝나 서술이 불필요한 성취기준"이 부적합 후보.

## 1. 범위 (항목 1 대응) ❓

| 결정 | 선택지 | 제안 |
|---|---|---|
| 학교급·학년 | 중등 먼저(국어와 동일) / 초등 먼저 / 중·고 | 국어와 같이 **중학교부터**, 이후 초·고 확장. 단 자료는 초등 예시가 있으므로 확인 필요 |
| 학년 범위 | 중1만 / 중1~3 | 시작은 **중1~3 전체 성취기준 파악, 생성은 1개 학년으로 파일럿** |
| 영역 | 수와 연산 / 변화와 관계 / 도형과 측정 / 자료와 가능성 | 4개 영역 모두 목록화, 파일럿은 2개 영역(예: 도형과 측정, 변화와 관계) |
| 교육과정 | 2022 개정 | ✅ (중학교는 2024 적용 학년 확인 필요) |
| 문항 유형 | 서술형 / 논술형(제한·확장) | 국어와 동일하게 응답 유형 선택, 수학은 "풀이 서술형"을 기본으로 추가 검토 |

## 2. 필요한 데이터 (항목 2~3 대응)

국어에서 만든 데이터를 수학용으로 다시 만들어야 한다.

| 국어 산출물 | 수학 대응 | 필요한 원자료 | 비고 |
|---|---|---|---|
| `standards.json` | 수학 성취기준 (예: [9수03-06]) | **수학과 교육과정 별책** ❓ 요청 | 코드 체계 ✅ 유사 |
| `content_elements.json` | 내용 요소(지식·이해/과정·기능/가치·태도) | 같은 교육과정 문서 | ✅ 구조 재사용 |
| `achievement_levels.json` | 성취수준 A~E (수학 영역별) | 교육부 **수학과 성취수준** 문서 ❓ 요청 | 국어와 달리 "예시 평가도구"는 이미 사용 안 하기로 결정 → 수학도 동일 적용? ❓ |
| `essayFeasibility` | 서술형 적합도 | 자동 분류 후 교사 검수 | 기준 재정의 필요 |
| `task_patterns.json` | 수학 과제 패턴 | 6개 PDF의 문항 분석 | 아래 참조 |
| `passage_length_guide.json` | **대체**: 풀이 서술 분량·소문항 수 가이드 | 자료 분석 | 지문 길이 → 소문항 수/단계 수 |
| `output_formats.json` | 경기형/서울형 | 이미 확보 | 수학 예시 포함 여부 확인 |
| 교과서 맥락(천재 등) | 수학 교과서 단원·용어·예시 | 수학 교과서 PDF ❓ | 국어와 같이 후순위 가능 |

**수학 과제 패턴(초안, 자료에서 관찰)**
- 개념 설명형: "~을 예를 들어 설명하시오"(초등)
- 비교·분류형: 직사각형/정사각형 비교
- 풀이 과정형: 식을 세우고 계산, 결론 서술
- 탐구·일반화형: 규칙 찾기, 식으로 일반화
- 오류 분석형: 잘못된 풀이를 찾아 고치기 (자료 추가 확인 필요)
- 실생활 모델링형: 상황을 수식으로 표현

## 3. 문항 모델 (항목 3 대응) 🔧

국어 모델 중 재사용 ✅: 평가 요소/채점 요소, 수준별 분할 점수, 기본 점수 20%, 배점 ≤ 20, 조건(id)→수준 서술, 소문항 dependsOn.

수학 추가 필드:
- `stimulus`: 지문 → `{ text, expressions[], figures[], tables[] }`
- `expressions`: LaTeX 문자열로 저장 (화면은 KaTeX)
- `figures`: 그림 설명 + 생성 방식(SVG 코드 / 이미지 파일 업로드 / "교사가 직접 삽입") ❓
- `solutionMethods[]`: 인정되는 풀이 2개 이상(대수적/도식적 등)
- `answer`: `{ final, steps[], units?, tolerance? }` — 검산용
- `verification`: 코드 검산 결과(통과/불일치)
- 채점기준 단계: "개념→식→계산→결론" 척도, 각 단계 분할 점수
- 채점 유의점: 단위 채점 여부, 계산 실수 연쇄 처리(= 감점 규칙이 아니라 **수준 서술**로 — 국어에서 결정한 방식 유지) ✅
- 성취수준 기반 "도움필요/보통/능숙" 피드백(서울형 표) 유지 가능

❓ **연쇄 오류 처리**(앞 계산 실수가 뒤 풀이에 영향): 국어에서 "감점 규칙 없이 수준 서술"로 결정했으므로, 수학도 "앞 단계 오류를 따른 일관된 풀이는 해당 단계까지 인정" 식의 수준 서술로 처리할지 확인.

## 4. 입력 화면 (항목 4 대응) 🔧

국어 입력 항목 유지: 학교급/학년/성취기준/평가 요소/응답 유형/배점/출력 형식.
수학 추가·변경:
- 영역 선택 → 성취기준 (수학은 코드가 영역별)
- **수식·그림 포함 정도**: 수식만 / 그림 필요 / 표·그래프 필요
- **풀이 방식 허용**: 한 가지 / 여러 가지
- **계산 난이도**: 숫자 범위(자연수/분수/소수/무리수 등)
- 단위 평가 여부, 계산기 허용 여부
- 교과서 연계: 출판사 선택 + "미선택=중립" ✅ (수학 교과서 자료 확보 후)

## 5. 생성 로직 (항목 5 대응) 🔧

국어 G0~G3를 수학으로 매핑:

| 국어 | 수학 |
|---|---|
| G0 평가 요소·역량 후보 제안 → 교사 확정 | ✅ 동일 (역량: 추론·문제해결·의사소통·정보처리·연결·창의 융합 중 선택) |
| G1 설계 | ✅ + 수학적 구조 설계(핵심 개념, 수치 설정, 풀이 단계 수) |
| G2 제시문 생성 | **상황·수치·그림 생성** (수치는 AI 임의 → 코드가 검증/선정) |
| G3 소문항·채점기준 | ✅ + 풀이·정답 생성 |
| (신규) **G3.5 코드 검산** | 최종 답, 중간 계산을 SymPy로 확인. 불일치 시 AI에 되먹임 후 재생성 |
| 조립/검증/AI 점검 | ✅ + 수식 렌더링 가능 여부 점검 |

핵심 결정 ❓
- **수치 생성 방식**: AI가 수치를 직접 정함 vs 코드가 수치 후보를 만들고 AI가 문장화. 후자가 검산에 유리(제안).
- **그림**: AI가 SVG/도형 코드를 생성(검증 어려움) vs 교사가 이미지 삽입 vs 글로 도형 설명만 제공(초기 제안: 1단계는 글+수식 중심, 그림은 SVG 템플릿(삼각형·사각형·원·좌표평면 등)으로 제한).
- 문항 예시 은행: 6개 PDF에서 수학 예시를 구조화(국어와 같은 방식).
- 주제 중복 방지: 국어와 동일하게 고도화.

## 6. 주요 기능·데이터 모델·기술 구조 (항목 6~8 대응) 🔧

- 화면 기능(부분 재생성 4가지, 보관함, 편집/저장, 어드민 탭): ✅ 그대로. 부분 재생성에 "**수치 바꾸기(같은 구조, 다른 숫자)**" 추가 제안 — 수학에서 유용.
- 수식 편집: LaTeX 입력 + 미리보기(KaTeX). 교사 편집 난이도 때문에 **수식 입력 UI** 필요 ❓
- 출력: 한글(HWP/HWPX)·워드 변환 시 **수식 표현**이 큰 이슈 — 국어 도구의 출력 방식 결정(내보내기 형식)과 연결. ❓
- 기술: FastAPI + React/TS 유지, **KaTeX, SymPy(백엔드 검산)** 추가. 모델은 Sonnet 5.5 유지(수학 정확도 부족 시 상위 모델 교차 검증 옵션).
- 데이터 모델: 국어 스키마 + `expressions`, `figures`, `answer`, `verification`.

## 7. 품질·법적 이슈 (항목 9 대응)

- 저작권: 수학은 교과서 지문 문제가 약함 — 문학 단원 같은 **부적합 사유가 거의 없음** ✅ 단순화. 교과서 문제 그대로 복제 금지는 유지.
- 사실 정확성 → **수학 정확성**: 코드 검산 + 교사 검토 완료 버튼 ✅.
- 정답 다중 풀이, 문제 오류(조건 부족·답 불일치)는 검증 항목에 추가 (validator V1~V31 기반 + 수학 규칙).

## 8. 단계(Phase) 제안

0. 자료 정리: 6개 PDF → 수학 예시 구조화, 교육과정 확보
1. 데이터: 수학 성취기준·내용요소·성취수준 JSON
2. 스키마 + validator(수학 규칙)
3. 프로토타입 생성(1개 영역, 중1) + SymPy 검산
4. 교사 시험 사용 → 보완
5. 웹 서비스화(국어와 공용 코드 검토)

1. 시작 학교급·학년·영역 (제안: 중학교, 1개 학년, 2개 영역)

## 자료 처리 메모
- 교육과정·성취수준 PDF: 텍스트 추출 가능하나 **수식 기호 일부 누락**(예: 분수). 수식이 있는 성취기준 해설·성취수준은 검수 필요.
- 성취수준: 성취기준에 따라 A/C/E 또는 A/B/D 등 3~4개만 서술된 경우가 있음(원문 그대로 유지).
- 교과서 PDF: 수식이 `;2#;` 같은 내부 코드로 추출돼 **본문 텍스트 분석에 부적합** → 단원 구조(차례)만 텍스트로, 그림·수식은 페이지 이미지 분석 필요.
- 중1 단원(5종 공통): 소인수분해, 정수와 유리수 / 문자와 식, 일차방정식, 좌표평면과 그래프 / 기본 도형과 작도, 평면도형의 성질, 입체도형의 성질 / 자료의 정리와 해석.
