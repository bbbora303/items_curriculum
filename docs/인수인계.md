## 2. 만든 것 (파이프라인)

```
교사 입력(성취기준·총점·난이도·과제 유형 자동/선택·교과서 선택/미선택)
 → G0 평가 요소·역량 후보(AI). 교과서를 골랐으면 그 책의 학습 목표를 입력으로 주고 요소마다 근거 목표(fromGoal)를 적게 함 → [교사가 화면에서 후보 중 1~4개를 고르거나 직접 씀(선택). 고르지 않으면 상위 3개 자동 확정]
 → G1 설계(AI): 과제 패턴, 소문항 골격(배점 합 검사), 그림 종류, needsDataset 판단. 교과서를 골랐으면 소재 후보 3개 중 하나를 설계 단계에서 정함(theme; 숫자 규칙의 상황과 안 맞으면 해제)
 → 수치 명세 확보: 있으면 사용 / 없으면 GN(AI)이 초안을 만들고 **멈추지 않고 이 문항 전용 임시 규칙으로 끝까지 생성**(10-21 결정). 교사는 완성된 문항 아래 '숫자 규칙 보기·고치기'에서 고치고 '이 규칙 확정'을 눌러야 같은 성취기준·유형이 재사용
 → 코드: 숫자 선택(template.pick_values)
 → G2 상황·그림(AI, 자리표시자 사용). 교과서를 골랐으면 G1이 정한 소재(코드가 시드로 고른 그 책의 단원 소재 후보 3개 중)로 제시문을 씀(scope_check.theme_block) → 그림 렌더 시험(실패 시 G2로 되돌림)
 → G3 소문항·수준 서술·방법별 예시답안·검산 식(checks)·유의점·교사 확인 사항(AI). 성취기준별 함정 안내는 항상, 교과서를 골랐으면 교과서의 성질·공식·풀이 방법·설명 원문 발췌를 근거로 제공(textbookBasis 기록). 풀이마다 tier(기본|확장) 표시
 → 코드: 자리표시자 채우기 → 검증기(M1~M30, 경고 W1~W17; 범위 W11/W12, 교과서 근거 W13) → 수치 변경 시험(다른 숫자 2조합으로 재검증)
     오류는 해결 방법까지 적어 G3에 되먹임(최대 3회, 같은 오류가 2번 더 반복되면 중단)
 → 풀이 판정(tiering.py, 전용 호출+반박 단계): 범위 밖 풀이를 코드가 확장 풀이로 고침. 3점↑ 소문항에 기본 풀이가 안 남으면 심각 이슈로 G3 재작성
 → AI 점검(**심각 이슈만** 1회 자동 수정; 보통·경미는 표시만) → 저장(item.json, item.template.json, meta.json, item.md, 그림 svg)
```
- **자료(표·목록)가 핵심인 문항**(예: 줄기와 잎 그림)은 '자료 묶음 번호+개수+범위'로 코드가 자료를 만들고 표(autoTable)도 코드가 그린다(4-19). 자료 규칙을 못 만들 때만 템플릿 없이 AI가 숫자를 정하고 코드가 검산만 한다.
- 그림은 AI가 `{type, params}`만 쓰고 `figures.py`가 SVG를 계산한다. 지원 7종: circle_sector, number_line, coordinate_plane(점·직선·반비례 곡선), polygon_labeled, angle_diagram, parallel_transversal, histogram. 목록상 19종 중 나머지(입체도형·전개도·작도 등)는 미구현.
- 검증기가 확인하는 것(M1~M30): 배점 합, 수준 점수(2~5단계, 엄격 감소, 최하 1점), 조건↔수준 연결, 예시답안의 **계산식 재계산(M26)**, 숫자가 명세 제약을 만족(M29), 그림 렌더, 교사 확인 사항 존재, 풀이 방법 2개 이상(경고). **개념적 오류·발문 모호성은 못 잡는다**(AI 점검이 일부 담당).

## 4. 시험 결과 (2026-10-20)
- 첫 생성 3건(부채꼴·일차방정식·통계): 모두 통과. 이때 발견·수정: 그림 params를 유형 이름으로 한 번 더 감싸 내는 문제(G2 직후 검사로 해결), AI 점검 출력 한도 초과, 제시문의 개념 오류("기본요금이 있는 요금을 정비례"라고 씀 — 검증기도 AI 점검도 처음엔 못 잡음 → AI 점검 지시문에 '진술의 참·거짓'과 '언급한 자료가 실제로 있는가' 추가).
- 템플릿 방식 시험: 부채꼴·일차방정식에서 **숫자만 바꾸기 동작 확인**(r=9→12→8 등, 정답·그림·비교까지 일치, 검증 오류 0).
- 영역별 일괄 8건: 9수01-05, 01-02, 02-07(첫 실행 실패→재실행 통과), 02-01, 03-05, 03-08, 04-01, 04-03 → 합계 추정 $4.74. 6건이 AI 점검 "수정 권고"(심각 0, 보통·경미 4~6개). 읽어 본 문항(정수 계산, 대푯값)에서 지적이 타당했음.
- AI 점검 반영(`revise.py`) 시험: 부채꼴에서 의견 4개 반영, "호 AB가 어느 호인지 모호" 등이 제시문에서 고쳐지고 자리표시자 유지, 검증 통과, 비용 약 $0.25.
- **웹 버그(사용자 보고)**: '숫자 규칙 확정' 버튼이 눌리지 않음 → 원인: 서버가 초안의 후보 개수를 세는 7~58초 동안 화면이 초안 없이 확인 카드를 띄움. 초안에 `candidateCount`/`samples`를 저장하고 초안이 준비된 뒤 상태를 바꾸도록 수정. 숫자 선택도 전체 열거(최대 1분+) → 무작위 시도(0.1초)로 변경. 사용자가 보고한 흐름 그대로 재현해 완료까지 확인함.
- 이번 세션의 API 사용 총액은 대략 $12~15(추정). 실제 금액은 콘솔에서 확인할 것.

## 4-1. 변경 (2026-10-21): 숫자 규칙 확정을 문항 아래로

## 4-13. 책 효과 입증 시도: 구조화 지표(A) + 블라인드 식별(B) (2026-10-22)
- **배경**: 4-12의 글자 겹침 지표로는 책 효과를 입증하지 못함(잡음 바닥과 구분 안 됨). 사용자 요청으로 A·B를 먼저 시행해 방향 확인.

## 4-15. 출력 토큰 한도 점검과 한도 초과 대응 (2026-10-23)

- 한계: 64,000에서도 잘리는 극단 사례는 여전히 가능(상향 후 재시도에서 100,000까지). 잘린 응답은 `raw_<단계>_truncated.txt`로 저장되어 원인 확인에 쓸 수 있다.

## 4-19. 자료 생성기: 통계(자료형) 문항의 숫자 바꾸기 (재논의 목록 7번, 2026-10-23)
- **문제**: 자료(점수 20개, 줄기와 잎 등)가 핵심인 문항은 숫자 규칙(낱개 숫자 조합)으로 못 만들어 '템플릿 없이' AI가 숫자를 정하고 숫자 바꾸기가 안 됐다.
- **설계(기존 구조를 거의 안 건드림)**: 자료를 **'자료 묶음 번호(씨앗) s + 개수 n + 값 범위 lo~hi'라는 낱개 숫자**로 표현한다. 수치 명세의 파생값 `data = dataset(s, n, lo, hi)`는 같은 s면 항상 같은 자료(정수 목록)를 만든다. 그래서 `numberBinding`, 숫자 뽑기(`pick_values`), 숫자만 바꾸기, 범위 고치기, 값 직접 지정, 검증 M26/M29, 수치 변경 시험이 그대로 동작한다. 자료는 가운데에 몰리는 분포(두 수의 평균)가 기본.
- **자료 함수**(`mathcheck.py`, 안전한 계산기): `dataset, len, sum, sorted, mean, median, mode(여러 개면 가장 작은 값), n_modes, mode_freq, count, count_between(lo 이상 hi 미만), rel_freq, data_range, distinct, item, min/max(자료)`. 제약 예: `n_modes(data)==1`, `is_int(median(data))`, `count_between(...)>=1`.
- **표는 코드가 그린다**(`scripts/datatable.py`): 문항 틀의 `stimulus.tables[].autoTable`에 `raw_row`(자료 나열, 10개씩 줄 바꿈) / `stem_leaf`(줄기와 잎, 잎은 작은 수부터) / `freq_table`(도수분포표+합계) / `rel_freq_table`(상대도수, 소수 또는 분수)를 쓰면 숫자를 채울 때 자료로 표를 만든다. 본문·예시답안의 자료는 `{{sorted(data)}}`, `{{median(data)}}`, `{{count_between(data, 60, 70)}}` 같은 자리표시자(쉼표로 이어 씀). 히스토그램·도수분포다각형 그림의 도수는 명세 파생값(c1..c5)을 자리표시자로 써서 같이 바뀐다.
- **AI 연결**(`generate.py`): 통계 영역·`needsDataset` 문항도 GN이 자료 규칙으로 명세를 만든다(DATASET_GN_RULES + 형식 예 `data/examples/numspec_dataset_example.json`), G2는 표를 autoTable로만 쓰고(DATASET_G2_RULE), 만든 표가 자료를 덮는지 G2 단계에서 미리 시험해 오류를 되먹임한다, G3는 자료를 자리표시자로 쓰는 규칙을 받는다. 자료 문항을 만들 수 없으면 예전처럼 템플릿 없이 진행(unsupported).
- **시험**: `scripts/test_dataset.py`(무료) 모두 통과 — 자료 고르기, 4가지 표, 난이도 3종, 다른 값이면 표가 달라짐. 실제 생성(천재 9수04-02, $0.80): 첫 시도에 검증 오류 0, 경고 0, 심각 0. 줄기와 잎·도수분포표·히스토그램·도수분포다각형이 나오는 문항이 만들어졌고 **숫자만 바꾸기(AI 없이)로 자료 20개, 표, 그림의 도수(1,6,7,5,1 → 1,4,8,4,3), 본문·예시답안이 모두 바뀌어 검증을 통과**했다. 웹 API로 숫자 규칙 보기, 범위 고치기(s 1~40), 값 직접 지정(조건을 어기면 이유를 쉬운 말로 설명), 범위 밖 값 거절 모두 확인.
- **한계**: 정수 자료만. 실제 생성은 성취기준 1개(9수04-02), 도수분포표·줄기와 잎 중심으로만 확인했다(9수04-01 대푯값, 04-03 상대도수는 코드 시험만). 검산식(checks)이 자명한 것(예: floor(mo/10)*10+mo%10)으로 채워질 수 있다. 자료 규칙의 쉬운 설명·표 모양은 사람이 눈으로 본 적이 없다(브라우저 미확인). 같은 s 범위가 넓으면 후보 계산이 느려질 수 있어 s는 300 이하로 안내했다.
